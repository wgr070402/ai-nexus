1.4 关键代码实现要点

  • 会话级模型绑定：chat_controller.dart 中 setActiveModel(id) 将模型持久化到当前会话，switchSession(id) 切换会话时自动恢复，实现「每个任务窗口模型隔离」。
  • 文件沙盒安全：file_service.dart 所有操作仅作用于 <appDocuments>/workspace，符合「以 Workspace 为沙盒」安全约定。
  • API Key 安全：模型 Key 存于 Android Keystore，备份/导出时不随 JSON 导出。
  • 备份白名单：dataKeys 白名单只允许备份受控 key，避免误写内部数据。
  • Termux 签名校验：内置 F-Droid / GitHub Release 双证书 SHA-256，校验失败回退本地 shell。

二、问题分析

2.1 Gradle 依赖下载被墙

根本原因：maven.google.com、services.gradle.org、pub.dev 在国内网络无法访问。
表现形式：flutter pub get / Gradle 构建卡死或超时。
修复方案：Gradle 仓库改用阿里云镜像，发行包改用腾讯镜像，pub 改用 pub.flutter-io.cn 镜像。

2.2 Gradle 守护进程内存溢出

修复方案：gradle.properties 设置 -Xmx4G。

2.3 flutter_secure_storage 版本冲突

根本原因：11.x 要求 compileSdk 37，项目为 36。
修复方案：锁定 ^9.2.2。

2.4 Kotlin 跨盘增量编译报错

修复方案：kotlin.incremental=false。

2.5 file_picker 传递依赖版本夹击

修复方案：dependency_overrides: flutter_plugin_android_lifecycle: 2.0.24。

2.6 Termux 真机联调核心问题（本轮最大阻塞点）

问题根本原因处置
调用被拒绝（签名/权限）Google Play 版 Termux 签名不符且 RUN_COMMAND 被阉割改装 GitHub Release 0.118.3
SecurityException权限只声明未运行时申请MainActivity 动态申请
BackgroundServiceStartNotAllowedExceptionEXTRA_BACKGROUND=false改为 EXTRA_BACKGROUND=true
命令发出后无结果OPPO 杀后台 o-kill(40)白名单 + 重启仍无效，放弃 Termux
最终结论：OPPO 手机后台强杀 Termux，依赖 Termux 的终端方案在目标设备不可用。改为参考 Operit AI 的 PRoot 内置 Ubuntu 方案（rootless、无需 Termux/root），采用「参考思路重写 + 首次运行时下载 rootfs」策略。
