1项目定位

以 Operit AI（系统自动化 + 完整 Linux 终端）、RikkaHub（多模型聊天体验）、拾忆 ShiYi（记忆 / 项目 / 技能 / 子代理）三者之长，合成一个 Android 应用：

  • 打开即聊天：启动直达单聊界面，像 RikkaHub 一样随手切模型。
  • 多智能体群聊：一个会话里混入「模型 / 智能体 / 专家」，最多 10 个，支持并行与讨论两种模式。
  • Operit 同款终端：内置完整 Linux，且可配置多种环境。
  • 四引擎：本地/云端模型 + DeepSeek Harness + Codex（OpenAI）+ Codex++（CodexPlusPlus），并列可选。

3我的需求汇总

核心诉求（按优先级）

  • P0打开 App 直接进聊天界面，功能对齐 Operit / RikkaHub。
  • P0聊天里能自由切换模型，模型输出进行中也能切（立即中断 + 用新模型重答）。
  • P0群聊：可自定义添加「模型 / 智能体 / 专家」，上限 10 个。
  • P0群聊支持「并行 / 讨论式」两种回复模式，可切换。
  • P0终端要跟 Operit 一样，且可配置各种环境。
  • P1引擎层：DeepSeek Harness + Codex + Codex++ 三套运行时（已澄清 Codex++ ≠ C++）。
  • P1合并三个项目的其余功能（记忆 / 搜索 / 技能 / 工作流 / 知识库 / 多模态 / 语音等）。
  • P1侧边栏新增 DeepSeek Harness 与 Codex 入口，未配置时先引导去终端配置，配好后点入口直接使用（见第 4 章）。
「专家」的定义（已确认）：专家 = 智能体（跟智能体完全一样，复用 Agent 库，不另建类型）。因此群成员底层只有两类：模型 与 智能体。
「Codex++」澄清（已确认）：不是 C++，是 Codex 与 Codex++（CodexPlusPlus） 两个东西。Codex 是 OpenAI 官方编码智能体；Codex++ 是它的增强启动器/管理工具。

5单聊模块设计（对齐 Operit / RikkaHub）

5.1 打开即聊天

  • App 启动默认直达聊天界面，不经过空首页。
  • 底部导航保留 5 Tab（聊天 / 群聊 / 终端 / 项目 / 设置），默认选中「聊天」。
  • 无 API Key 时聊天页显示引导，而不是白屏。

5.2 模型自由切换

  • 聊天顶部固定模型选择器（沿用现有 activeModelId）。
  • 切换即时生效，下一条用新模型；支持已配置的所有供应商。

5.3 流式输出中切换（关键新能力）

用户确认：「立即中断，用新模型重答」
  1. 切换模型 → 中止当前 HTTP 流（取消订阅 + 关闭连接）。
  2. 当前正在生成的助手消息立即停止，标记为中断。
  3. 用新模型重新生成这一条（用户消息不变，只重跑回答）。

代价：多消耗一次 token，已接受。技术前提：给 LlmService.streamChat 加可取消能力。

6群聊模块设计（多智能体，最多 10 个）

6.1 成员统一模型（核心改动）

现 GroupSession.agentIds 只存 Agent id，改为统一的群成员抽象：

字段说明
typemodel（裸模型） / agent（智能体·含专家）
显示名显示在群聊里的名字
model 型直接挂一个 ModelConfig，无角色设定
agent 型引用 Agent，带入身份 / 系统提示词 / 模型 / 技能
  • 模型成员：回复用默认身份，无系统提示词。
  • 智能体 / 专家成员：从 Agent 库选（同一池子）。
  • 新建群聊弹窗分两栏：模型库 / 智能体库，可混选。

6.2 上限 10

  • 创建 + 编辑时硬校验，超过 10 禁止加入并提示。
  • 群详情顶部显示「N / 10」。

6.3 两种回复模式（都要，可切换）

用户确认：并行 / 讨论式 两种都做，建群可选、之后可改。
模式行为特点
并行每个成员各自基于「用户消息 + 历史 + 自己身份」同时回复快；成员间互不知晓
讨论式按加入顺序轮流发言，后一个能看到前一个的回复再回答像圆桌；慢、token 消耗更高

两种模式都流式、都可中断。

7终端模块设计（对齐 Operit + 多环境）

7.1 目标

达到 Operit 同款终端，核心是内置完整 Linux，开箱即用（不依赖用户装 Termux）。界面为深色代码风格（见 4.3）。

Operit 终端特性现状规划
内置完整 Linux骨架proot 内置 rootfs 为默认
bash / apt / python骨架补齐 rootfs + 常用包
命令历史、彩色输出未做新增
SSH未做规划
挂载手机文件系统未做规划
AI 复用同一终端 (run_terminal)未做让 Agent 也能跑命令
Termux 回退骨架保留备选

7.2 可配置多种环境（用户新增需求）

  • 多环境预设：Ubuntu 24.04 / Debian / Alpine / Kali 等可切换。
  • 自定义环境：导入自己的 rootfs。
  • 环境内配置：Python 版本、Node 版本、常用包可指定。
  • 环境管理：创建 / 切换 / 删除独立环境，互不影响。
  • 与 AI 联动：Agent 执行命令时可指定跑在哪个环境。

8引擎层：模型 / DeepSeek Harness / Codex / Codex++

四套运行时并行可选，会话数据各自独立（对齐拾忆「双引擎」思路，扩展到四引擎）。

① 本地 / 云端模型

DeepSeek / OpenAI / Anthropic / Gemini / Kimi / 智谱 / 通义 / OpenRouter / Ollama，流式调用。

② DeepSeek Harness

DeepSeek 开源的 agent harness，理念「一切皆插件」，底层基于 Cordis 框架。

🔗 deepseek-ai/deepseek-harness

现骨架：deepseek_harness_adapter / http_deepseek_harness_adapter，通过 npx @deepseek-ai/dsh web（默认 127.0.0.1:3080）接入。

注意：DeepSeek Harness 处于 developer preview，迭代快、有破坏性变更，接入需做版本隔离。

③ Codex（OpenAI Codex CLI）

OpenAI 官方命令行编码智能体，用于代码生成、重构、调试、执行。

🔗 openai/codex

现骨架：codex_adapter / codex_page。

④ Codex++（CodexPlusPlus）

面向 OpenAI Codex / ChatGPT 桌面应用的外部启动器与管理工具（约 30k star，Rust / Tauri）。

🔗 BigPizzaV3/CodexPlusPlus
  • 通过 Chromium DevTools Protocol + 本地服务，实现供应商切换、协议转换、会话管理、界面增强，不改 app.asar。
  • 两个入口：Codex++（静默启动官方应用并加载配置）、Codex++ 管理工具（供应商 / 模型 / 工具插件 / 会话 / 脚本 / 诊断）。
  • 借鉴点：它的「供应商切换 + 协议转换」思路，可让我们把第三方模型接进 Codex 类编码工作流。
