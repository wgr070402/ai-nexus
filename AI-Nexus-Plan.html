AI Nexus 开发制作文档

单聊 + 群聊（多智能体）+ 终端 + 四引擎 · 即将进入开发阶段
Flutter / Android 开发准备阶段 更新：2026-08-25

1项目定位

以 Operit AI（系统自动化 + 完整 Linux 终端）、RikkaHub（多模型聊天体验）、拾忆 ShiYi（记忆 / 项目 / 技能 / 子代理）三者之长，合成一个 Android 应用：

  • 打开即聊天：启动直达单聊界面，像 RikkaHub 一样随手切模型。
  • 多智能体群聊：一个会话里混入「模型 / 智能体 / 专家」，最多 10 个，支持并行与讨论两种模式。
  • Operit 同款终端：内置完整 Linux（proot Ubuntu 24.04），开箱即用。
  • 四引擎：本地/云端模型 + DeepSeek Harness + Codex（OpenAI） + Codex++（CodexPlusPlus），并列可选。
  • 环境状态检测：终端配置后自动检测 Python/Node/Shell/DeepSeek Harness/Codex 状态（运行中/未配置/配置失败）。

3需求汇总

核心诉求（按优先级）

  • P0打开 App 直接进聊天界面，功能对齐 Operit / RikkaHub。
  • P0聊天里能自由切换模型，模型输出进行中也能切（立即中断 + 用新模型重答）。
  • P0群聊：可自定义添加「模型 / 智能体 / 专家」，上限 10 个。
  • P0群聊支持「并行 / 讨论式」两种回复模式，可切换。
  • P0终端要跟 Operit 一样（内置 proot Ubuntu 24.04），且可在终端内配置环境。
  • P1引擎层：DeepSeek Harness + Codex + Codex++ 三套运行时。
  • P1合并三个项目的其余功能（记忆 / 搜索 / 技能 / 工作流 / 知识库 / 多模态 / 语音等）。
  • P1侧边栏新增 DeepSeek Harness 与 Codex 入口，未配置引导 → 终端配置 → 点亮即用。
  • P1环境状态检测：Python/Node/Shell/DeepSeek Harness/Codex 三态显示（运行中/未配置/配置失败）。
  • P1补齐遗漏功能：Operit 工具分类/权限模式、RikkaHub ASR/Prompt模板/二维码、拾忆跨会话查阅/项目目录/思考/活人感/SOCKS5 等。
「专家」的定义（已确认）：专家 = 智能体（跟智能体完全一样，复用 Agent 库，不另建类型）。因此群成员底层只有两类：模型 与 智能体。
「Codex++」澄清（已确认）：不是 C++，是 Codex 与 Codex++（CodexPlusPlus） 两个东西。Codex 是 OpenAI 官方编码智能体；Codex++ 是它的增强启动器/管理工具。

4.18 交互流程：引擎入口（未配置 → 终端配置 → 点亮即用）

用户确认：点入口 → 未配置先引导去终端 → 终端启动本地服务 → 回侧边栏状态点变青 → 再点即直接使用。
  1. 侧边栏：DeepSeek Harness 和 Codex 各有一个状态点（灰/青）。
  2. 点击灰点入口 → 跳转到「未配置引导页」（4.6），显示三步说明。
  3. 「去终端配置」按钮 → 跳转到终端界面（4.5），自动填入/提示启动命令。
  4. 执行命令成功 → 终端显示服务就绪信息，环境检测输出各状态。
  5. 返回侧边栏 → 状态点自动变青（本地服务探活成功）。
  6. 再次点击青点入口 → 直接进入对话/编码工作台（4.7/4.8）。

4.19 交互流程：环境状态检测

  1. 终端启动时 / 用户触发「检查并开始」时，系统对每个环境执行探活命令。
  2. 检测范围：Python（python3 --version）、Node（node --version）、Shell（bash --version）、DeepSeek Harness（端口 3080 探活）、Codex（codex --version）。
  3. 结果映射：成功 → 运行中（青点），未安装 → 未配置（灰点），异常 → 配置失败（红点）。
  4. 状态展示于「环境状态面板」（4.13）和侧边栏状态点。
  5. 配置完成后自动重新检测并更新状态。

  • 切换即时生效，下一条用新模型；支持已配置的所有供应商。

5.3 流式输出中切换（关键新能力）

用户确认：「立即中断，用新模型重答」

  2. 当前正在生成的助手消息立即停止，标记为中断。
  3. 用新模型重新生成这一条（用户消息不变，只重跑回答）。

6群聊模块设计

6.1 成员统一模型

字段说明
typemodel（裸模型） / agent（智能体·含专家）
显示名显示在群聊里的名字
model 型直接挂一个 ModelConfig，无角色设定
agent 型引用 Agent，带入身份 / 系统提示词 / 模型 / 技能
  • 模型成员：回复用默认身份，无系统提示词。
  • 智能体 / 专家成员：从 Agent 库选（同一池子）。
  • 新建群聊弹窗分两栏：模型库 / 智能体库，可混选。

6.2 上限 10

  • 创建 + 编辑时硬校验，超过 10 禁止加入并提示。
  • 群详情顶部显示「N / 10」。

6.3 两种回复模式

用户确认：并行 / 讨论式 两种都做，建群可选、之后可改。
模式行为特点
并行每个成员各自基于「用户消息 + 历史 + 自己身份」同时回复快；成员间互不知晓
讨论式按加入顺序轮流发言，后一个能看到前一个的回复再回答像圆桌；可自定义调整顺序（拖拽/排序按钮）

7终端模块设计

用户确认：终端和 Operit AI 一模一样，只保留 Ubuntu 24.04。

7.1 目标

与 Operit AI 完全一致的终端体验：内置完整 Linux（proot Ubuntu 24.04），开箱即用（不依赖用户装 Termux）。深色代码风格界面。
